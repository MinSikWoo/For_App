# 업무 매뉴얼: 일본어 단어 카드 앱 테스트하기

## 목표
업데이트를 올리기 전에, 실제 사람처럼 앱을 써 보면서 버그와 불편한 점을 찾는다. 단어와 문장 데이터가 맞는지도 확인한다.

## 언제 하나
- 새 기능을 넣었거나 화면을 크게 바꿨을 때 (필수)
- 단어나 문장을 추가·수정했을 때 (데이터 검사만이라도 필수)
- 대표님이 "테스트 돌려줘"라고 할 때

## 필요한 것
- `.env` 의 `APP_PASSWORD` (잠금 해제용). 없으면 대표님께 비밀번호를 물어본다.
- 최신 빌드: `python3 tools/build_pwa.py` 로 `docs/cards/` 를 먼저 새로 만든다.

## 순서

### 1. 데이터 검사 (1분)
```
python3 tools/qa_check_data.py
```
- 결과: 화면 요약과 `.tmp/qa/data_check.json`
- 괄호 짝이 틀리거나 뜻이 겹치는 단어가 나오면, 올리기 전에 고친다.

### 2. 사람처럼 써 보는 자동 테스트 (10~20분)
```
node tools/qa_playtest.js
```
- 사용법(포트, 반복 횟수 등)은 파일 맨 위 설명을 따른다.
- 결과: `.tmp/qa/` 아래 발견 목록과 스크린샷
- 스크린샷을 직접 열어서 화면이 깨진 곳이 없는지 눈으로 확인한다.

### 3. 일본어 내용 검수 (단어·문장을 새로 넣었을 때)
- 새로 넣은 단어·문장만 서브에이전트에게 검수시킨다. 확인할 것은 읽는 법, 뜻, 번역, 빈칸 답이 하나인지.
- 결과는 `.tmp/qa/content_review.md` 형식을 따른다.

### 4. 정리해서 보고
- 중요도 높음/중간/낮음으로 나눠서 대표님께 쉬운 말로 보고한다.
- 대표님이 고칠 것을 고르기 전에는 고치지 않는다. 단, 앱이 아예 안 열리는 문제는 바로 보고한다.

## 알려진 한계
- 테스트 브라우저에서는 소리가 나지 않는다. 발음 버튼은 눌리는지만 확인된다.
- 실제 휴대폰 설치(홈 화면 아이콘)는 자동 테스트로 확인할 수 없다. 설치에 필요한 조건(앱 정보 파일, 아이콘, 오프라인 파일)만 확인한다.
- 일본어 검수는 AI가 하므로, "확인 필요" 항목은 사람이 한 번 더 본다.

## 고친 문제가 다시 생기지 않게
- 테스트에서 찾은 버그를 고치면, 그 상황을 `tools/qa_playtest.js` 시나리오에 추가해서 다음 테스트부터 자동으로 확인되게 한다.
- 이 매뉴얼에 새로 알게 된 주의점을 적는다.
